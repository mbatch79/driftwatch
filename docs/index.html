How it works

Once a week, and on demand, an unattended pipeline runs on GitHub's infrastructure. It has no opinions and no large-language-model in the critical path, so it cannot invent a change that didn't happen.

  1. Fetch. Each vendor's OpenAPI spec or changelog is pulled from its own repository and compared to the exact commit we checked last time. Nothing is reported twice; nothing is skipped.
  2. Diff. Structural comparison: endpoints, parameters, request and response fields, schema types, enums, deprecation flags. Cosmetic edits never leave this step.
  3. Verify. A second, independent check re-locates every finding in the raw source from its locator alone. Anything it can't reproduce is discarded, not softened.
  4. Match. On paid plans we hold your lockfile and source. A change is urgent because line 42 calls it, not because a model guessed.
  5. Deliver. Urgent findings push to Slack or email; the rest arrive in a weekly brief. Every line carries the commit range and a locator you can check yourself.

Start free, in your CI

The free GitHub Action reads your lockfile on every build and flags any verified breaking change that touches a package you depend on. No account, no key.

# .github/workflows/driftwatch.yml
on: [push, pull_request]
jobs:
  driftwatch:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: mbatch79/driftwatch/action@main

The job summary lists what was found and where. Nothing is sent anywhere; the feed it checks against is public JSON.
